# bragfile-site

Landing page for [bragfile](https://github.com/jysf/bragfile000), built during the
AdaL website hackathon. Every step of building it was captured by the tool the page
is about; the log renders on the page.

## Setup

```bash
just install    # or: npm install --include=dev
just build      # do this first — confirm the stack builds before anything else
just dev
```

Requires Node 22 or later (Astro 6+).

> **Pitfall:** if your shell exports `NODE_ENV=production` (some Node
> version managers do this), `npm install` silently skips devDependencies
> and the lint script will be missing. Use `just install`, which forces
> `--include=dev` — the justfile exists for this reason.

## Stack

Astro 7, static output. Plain CSS with tokens in `src/styles/tokens.css` and
component styles in scoped `<style>` blocks. No CSS framework — Astro 7 ships
Vite 8 with the Rolldown bundler, which `@tailwindcss/vite` doesn't yet support,
and the failure only surfaces at build time.

Fonts come from Astro's built-in Fonts API: downloaded, subset and self-hosted at
build time, so there's no third-party font request at runtime. That matters on a
page arguing your data never leaves your machine.

## Token enforcement

```bash
npm run lint
```

stylelint is configured with `stylelint-declaration-strict-value` so a raw hex or
a raw font size anywhere outside `tokens.css` fails the check. This is what keeps
day-6 output consistent with day-1 output when an agent is writing most of the CSS.

## Social card

```bash
npm run og      # builds public/og.png from src/data/log.json
```

The card renders your real entry count and a bar chart bucketed from the actual
log, using the same tokens as the site. Regenerate it at freeze time so the link
preview shows final numbers.

## Updating the log

```bash
npm run log     # brag export --format json --project bragfile-site
```

Commit `src/data/log.json`. Run again at freeze time, after the final entry.

## Deploy

Cloudflare Worker `bragfile`, custom domain `bragfile.jysf.org`. Deployed
automatically by Workers Builds: every push to the GitHub repo builds
(`npm run build`) and deploys `dist/` plus `worker/`. No manual step.

The Worker serves the static site and the first-party analytics endpoints:
`POST /api/track` (ingest) and `GET /sitevisits` (dashboard, unlinked).
Config lives in `wrangler.jsonc`, including the `STATS` KV namespace binding.

Cloudflare Web Analytics is cookieless and needs no consent banner — a cookie
dialog on this particular page would undercut the whole pitch.

## Metrics

- **Install command copy-clicks** — the conversion that matters. Wired in
  `src/components/CopyButton.astro`.
- **GitHub click-through** — secondary.
- **Scroll depth to the log section** — does anyone get far enough to notice the
  recursive concept? If not, move it up the page.
- **Release download counts** via the GitHub API — closest proxy for installs,
  since Homebrew analytics don't cover custom taps.

## Structure

```
src/
  styles/tokens.css     the design system — edit here, nowhere else
  layouts/Base.astro    head, meta, OG tags, font loading
  components/           the five permitted components (+ Freshness)
  lib/log.ts            loads and shapes the brag export
  data/log.json         generated by scripts/export-log.sh — commit it
  pages/index.astro     six sections, copy marked TODO
```

`DESIGN-SPEC.md` is the brief. `SESSIONS.md` has the AdaL session prompts.
`AGENTS.md` is the project context the agent reads.
